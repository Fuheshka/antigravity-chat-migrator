## Краткий обзор

**Antigravity Chat Migrator** (`agy-migrator`) - надежная утилита с нулевыми внешними зависимостями, созданная для исправления, категоризации и синхронизации истории диалогов в **Google Antigravity IDE**.

При переименовании каталогов проекта, переносе репозиториев на другой диск или переходе между версиями среды Antigravity часто отвязывает существующие чаты и помещает их в общий сворачиваемый раздел **«Outside of Project»** (Вне проекта) на боковой панели. В результате теряются заголовки, ломается привязка к проектам, а история диалогов становится разрозненной.

`agy-migrator` устраняет коренную причину этой проблемы: утилита детально анализирует и синхронизирует базы данных траекторий SQLite, реестр рабочих пространств `projects.json`, текстовые аннотации Protobuf (`.pbtxt`) и бинарный кэш языкового сервера (`agyhub_summaries_proto.pb`) на macOS и Windows.

## Описание проблемы «Outside of Project»

### Почему диалоги отвязываются от проектов

Среда Google Antigravity связывает историю диалогов с рабочими пространствами через многоуровневую систему хранения:

```
┌────────────────────────────────────────────────────────────────────────┐
│                     Хранилище данных Antigravity IDE                   │
├────────────────────────────────────────────────────────────────────────┤
│ 1. Реестр проектов:     ~/.gemini/config/projects.json                 │
│    Связывает путь URI (file:///path/to/project) с UUID project_id      │
│                                                                        │
│ 2. Базы траекторий:     ~/.gemini/antigravity/conversations/<id>.db    │
│    Таблица: trajectory_metadata_blob                                   │
│    Поле 18 Protobuf: project_id (отсутствует или "outside-of-project") │
│    Поле 1 Protobuf:  WorkspaceInfo (URI файла, Git-ветка, репозиторий) │
│                                                                        │
│ 3. Общая база резюме:   ~/.gemini/antigravity/conversation_summaries.db │
│    Таблица: summaries (conversation_id, title, project_id, summary)    │
│                                                                        │
│ 4. Кэш языкового сервера: ~/.gemini/antigravity/agyhub_summaries_proto.pb│
│    Бинарный блоб Protobuf, загружаемый в память процессом language_server│
│                                                                        │
│ 5. Аннотации диалогов:  ~/.gemini/antigravity/annotations/<id>.pbtxt   │
│    Текстовый формат Protobuf с заголовком и меткой времени активности  │
└────────────────────────────────────────────────────────────────────────┘
```

Попадание диалога в категорию **«Outside of Project»** происходит по одной из следующих причин:

1. **Незарегистрированное рабочее пространство:** Папка проекта была переименована, перенесена или открыта до того, как Antigravity сгенерировал запись `project_id` в `projects.json`.
2. **Рассинхронизация метаданных:** Поле 18 Protobuf внутри файла `<conversation_id>.db` оказалось пустым либо явно содержит служебную строку `"outside-of-project"`.
3. **Устаревший глобальный индекс:** Запись в `conversation_summaries.db` ссылается на неверный или удаленный `project_id`.
4. **Конфликт бинарного кэша Protobuf:** Даже при ручной правке SQLite фоновый демон `language_server` держит в оперативной памяти бинарный кэш `agyhub_summaries_proto.pb`. При закрытии редактора IDE сбрасывает устаревший кэш из памяти на диск, перезаписывая ручные изменения.
5. **Отсутствие аннотаций:** Без файла `<conversation_id>.pbtxt` интерфейс Antigravity не может отобразить заголовок чата, отображая пустые строки или временные идентификаторы.

### Правило холодной записи (Cold-Disk Invariant)

> [!IMPORTANT]
> **Категорически запрещено изменять базы данных Antigravity при запущенном редакторе или его языковом сервере.**
> Активные процессы Antigravity удерживают эксклюзивные блокировки SQLite (`PRAGMA locking_mode = EXCLUSIVE`) и хранят кэш резюме в оперативной памяти. Изменение файлов на горячем диске приводит к ошибкам блокировки базы данных, повреждению записей или возврату старого состояния при выходе из IDE.
>
> `agy-migrator` автоматически реализует **правило холодной записи**: утилита проверяет запущенные PID процессов, предупреждает пользователя и поддерживает режим `--watch`, который ожидает безопасного закрытия Antigravity перед синхронизацией.

## Команды CLI

Интерфейс `agy-migrator` построен на библиотеке Rich с высокой контрастностью и поддержкой переключения языков (`--lang ru` или `--lang en`, по умолчанию используется язык операционной системы).

### 1. `audit` - Диагностика и проверка состояния (без изменения файлов)

Сканирует все диалоги, проверяет привязку к рабочим пространствам, находит незарегистрированные каталоги и фиксирует недостающие аннотации, не меняя ни одного байта на диске:

```bash
agy-migrator audit
```

```text

├──────────────────────────────────────────┼────────────┼──────────────────────┤
│ Всего просканировано диалогов            │        353 │  ✔ Готово к работе   │
│ Привязано к проектам                     │        348 │      ✔ В норме       │
```

### 2. `fix` - Комплексное восстановление и синхронизация

Выполняет сквозное атомарное восстановление всех компонентов:
1. Создает резервный снимок баз и кэшей с меткой времени.
2. Регистрирует обнаруженные рабочие пространства в `projects.json`.
3. Записывает канонический `project_id` в поле 18 таблицы `trajectory_metadata_blob` в SQLite.
4. Генерирует недостающие аннотации `.pbtxt` с заголовками, извлеченными напрямую из запросов пользователя в `transcript.jsonl`.
5. Обновляет бинарный кэш `agyhub_summaries_proto.pb`.
6. Синхронизирует записи в `conversation_summaries.db`.

```bash
# Стандартный запуск (с запросом подтверждения при открытом IDE)
agy-migrator fix

# Режим симуляции (dry-run, просмотр изменений без записи на диск)
agy-migrator fix --dry-run

# Режим сторожа: ожидать закрытия Antigravity IDE и сразу выполнить синхронизацию
agy-migrator fix --watch

# Принудительный режим: выполнить синхронизацию даже при активных процессах (для экспертов)
agy-migrator fix --force
```

```text
ℹ️  Режим симуляции (dry-run). Изменения не будут записаны на диск.

  • Просканировано диалогов: 353
  • Обновлено диалогов: 5
  • Сгенерировано аннотаций: 3
  • Зарегистрировано проектов: 2

✔ Синхронизация успешно завершена.
```

### 3. `watch` - Фоновый сторож процессов

Отслеживает жизненный цикл процессов Antigravity IDE и `language_server`. Как только пользователь закрывает среду разработки, утилита автоматически выполняет синхронизацию на холодном диске:

```bash
agy-migrator watch
```

```text
⏳ Сторож активен: отслеживание жизненного цикла Antigravity IDE...
  [IDE активна: PID 12312, 12315] Ожидание завершения процессов...
  [IDE закрыта] Запуск синхронизации на холодном диске...
✔ Синхронизация успешно завершена.
```

### 4. `rollback` - Восстановление из резервного снимка

Перед каждой операцией `fix` утилита создает точку восстановления в каталоге `~/.gemini/antigravity/backups/migrator/`. Команда `rollback` позволяет моментально вернуть базы данных, бинарные кэши и аннотации к исходному состоянию:

```bash
# Список всех доступных резервных копий
agy-migrator rollback --list

# Откат к последней сохраненной копии
agy-migrator rollback

# Откат к конкретному снимку по идентификатору
agy-migrator rollback snapshot_20260930_001500
```

## Лаунчер для Windows в один клик (`run_fix.bat`)

Для пользователей Windows в портативный ZIP-архив включен скрипт `run_fix.bat`:

1. Проверяет наличие запущенных процессов `Antigravity.exe` и выводит напоминание закрыть редактор.
2. Запускает диагностику `agy-migrator.exe audit` с выводом наглядной таблицы.
3. Запрашивает подтверждение пользователя перед началом записи.
4. Выполняет `agy-migrator.exe fix` с автоматическим созданием резервной копии.
5. Отображает итоговый отчет и ожидает нажатия любой клавиши.

## Архитектура проекта

```
src/antigravity_migrator/
├── __init__.py               # Метаданные пакета и версия
├── cli.py                    # Команды консольного интерфейса на Typer и Rich
├── paths.py                  # Кроссплатформенный менеджер путей (macOS и Windows)
├── proto_codec.py            # Битовый Protobuf-кодек на чистом Python без зависимостей
├── db_manager.py             # Работа с базами SQLite с busy_timeout и атомарным UPSERT
├── project_registry.py       # Регистрация каталогов в projects.json и нормализация URI
├── annotation_generator.py   # Извлечение заголовков из transcript.jsonl и создание .pbtxt
├── backup_manager.py         # Управление снимками резервных копий и откат
├── process_watcher.py        # Определение процессов Antigravity (psutil / системные утилиты)
├── service.py                # Высокоуровневый сервис оркестрации (аудит и синхронизация)
├── ui_renderer.py            # Отрисовка контрастных баннеров, таблиц и полос прогресса
└── i18n.py                   # Двуязычный словарь локализации (RU и EN)
```

### Ключевые инженерные решения
- **Битовый Protobuf-кодек без внешних библиотек (`proto_codec.py`):** Парсит и упаковывает типы полей Protobuf (0, 1, 2, 5) напрямую через побитовые сдвиги (`<<`, `>>`, `&`, `|`) в стандартном Python. Не требует компилятора `protoc` или библиотеки `protobuf`.
- **Защита от блокировок SQLite (`db_manager.py`):** Все подключения используют `PRAGMA busy_timeout = 5000`, исключая падения из-за временных блокировок базы данных.
- **Интеллектуальное извлечение заголовков (`annotation_generator.py`):** Автоматически формирует понятные заголовки чатов из текста первого пользовательского сообщения в `transcript.jsonl`, отсекая служебные команды (`/goal`, `/using-superpowers`, `/vibe-coding`) и разметку markdown.
- **Единые кроссплатформенные пути (`paths.py`):** Одинаково надежно работает с дисками Windows (`file:///C:/Users/...`) и путями macOS (`file:///Users/...`) с соблюдением стандартов RFC 3986.
