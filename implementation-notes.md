## 2026-09-29: Промпт 1.1 — Инициализация структуры проекта и кроссплатформенный PathManager

### Принятые архитектурные решения
1. **Нулевые внешние зависимости для тестов (Ponytail YAGNI):**
   - Тесты написаны с использованием стандартного `unittest` и `unittest.mock`, что позволяет запускать весь тестовый набор командой `PYTHONPATH=src python3 -m unittest discover tests` без необходимости предварительной установки `pytest` или активации виртуального окружения. При этом тесты на 100% совместимы с `pytest`.
2. **Кроссплатформенная модель путей (`PathManager`):**
   - Вычисление базовых путей опирается на `Path.home() / ".gemini"`:
     - macOS: `~/.gemini/antigravity/` и `~/.gemini/config/`.
     - Windows: `%USERPROFILE%\.gemini\antigravity\` и `%USERPROFILE%\.gemini\config\`.
   - Поддержаны явные переопределения через конструктор `PathManager(data_dir=..., config_dir=...)` и переменные окружения (`GEMINI_DATA_DIR`, `GEMINI_CONFIG_DIR`), что гарантирует простоту интеграционного тестирования без засорения пользовательских директорий.
   - Метод `normalize_uri` приводит локальные пути macOS и Windows к стандарту `file:///...` Antigravity (включая Windows диски `file:///C:/...` и экранирование обратных слэшей).
3. **Структура репозитория:**
   - Ветка по умолчанию для разработки: `dev`.
   - Пакет расположен в `src/antigravity_migrator/`.
   - Конфигурация в `pyproject.toml` по стандарту PEP 621 / setuptools.

### Результаты тестирования

## 2026-09-29: Промпт 1.2 — Чистый Python Protobuf кодек (proto_codec)

### Принятые архитектурные решения
1. **Zero-dependency Protobuf кодек (Ponytail):**
   - Полный отказ от `.proto` файлов и компилятора `protoc`. Сериализация и десериализация реализованы на чистом Python с использованием битовых операций (`<<`, `>>`, `&`, `|`) и `bytearray`.
2. **Безопасность и отказоустойчивость парсера (`parse_proto`):**
   - Защита от зацикливания: чтение varint ограничено 10 байтами (предел 64-битного varint).
   - Защита от поврежденных данных: проверка выхода за границы буфера при чтении wire_type 1 (8 байт), wire_type 2 (length-delimited) и wire_type 5 (4 байта).
   - При встрече поврежденного суффикса или обрыва данных парсер возвращает корректно прочитанные до момента сбоя поля без выброса исключений (`IndexError`, `ValueError`).
3. **Модификация метаданных Antigravity (`inject_project_id_into_metadata`):**
   - Обеспечивает атомарную замену или добавление поля 18 (`project_id`) без дублирования.
   - Поддерживает опциональное обновление или вставку поля 1 (`WorkspaceInfo`).
   - Сохраняет все остальные поля `TrajectoryMetadata` (поле 6 `conversation_id`, поле 7 `workspace_uri` и др.) в исходном виде.
4. **Формирование `WorkspaceInfo` (`build_workspace_info`):**
   - Корректно упаковывает поля 1 и 2 (URI воркспейса), вложенное поле 3 (Git-метаданные repo + git_url при наличии) и поле 4 (ветка).

### Результаты тестирования
- `tests/test_proto_codec.py`: 12 тестов, 100% pass (0.01s).
- Проверены:
  - `encode_varint`: 0, 1, 127, 128, 300, отрицательные числа (64-битный two's complement).
  - `encode_field`: wire_type 0, 1, 2, 5 и обработка некорректных типов.
  - `parse_proto`: корректные данные, пустые буферы, битые и усеченные varint/длины, извлечение валидной части до точки сбоя.
  - `build_workspace_info`: с Git-метаданными, без Git, пустые входные данные.
  - `inject_project_id_into_metadata`: вставка в пустые метаданные, перезапись существующего поля 18, обновление поля 1 (`WorkspaceInfo`), устойчивость к битым входным блобам.
  - Round-trip модификация вложенного поля 17 (`TrajectoryMetadata`) и поля 18 (`project_id`) внутри симулированного `CascadeTrajectorySummary`.
- Общий тестовый набор: 21 тест, 100% pass.

## 2026-09-29: Промпт 1.3 — Модуль DatabaseManager для SQLite баз Antigravity (db_manager)

### Принятые архитектурные решения
1. **Безопасная работа с SQLite и защита от блокировок (Ponytail YAGNI):**
   - Все обращения к базам данных используют контекстные менеджеры `with sqlite3.connect(...) as conn:` с транзакционной обработкой (автоматический commit при успехе и rollback при исключении).
   - Для всех соединений выставлен `PRAGMA busy_timeout = 5000` и параметр `timeout=5.0` в `sqlite3.connect()`, что защищает от конфликтов параллельного доступа при работе фоновых демонов и Language Server.
2. **Извлечение Workspace URI (`extract_workspace_uri`):**
   - Читает строку `id = 'main'` из таблицы `trajectory_metadata_blob`.
   - В первую очередь инспектирует вложенное сообщение `WorkspaceInfo` (Поле 1, подполе 1 `uri`), либо прямую строку в поле 1.
   - В качестве резервного источника проверяет Поле 7 (`workspace_uri`).
   - Безопасно возвращает `None` при отсутствии файла, отсутствии таблицы или поврежденном Protobuf-блобе.
3. **Атомарная запись Protobuf-метаданных (`update_trajectory_metadata`):**
   - Использует `INSERT OR REPLACE INTO trajectory_metadata_blob (id, data) VALUES ('main', ?)`.
   - Автоматически создает родительские каталоги и схему таблицы при их отсутствии.
4. **Управление реестром `conversation_summaries.db`:**
   - `load_conversation_summaries`: формирует словарь с ключом `conversation_id`, безопасно читая `title`, `project_id` и `raw_summary`. Возвращает пустой словарь при отсутствии файла или таблицы.
   - `update_summary_record`: реализует гибкий UPSERT — при наличии существующей записи обновляет только переданные поля (`title`, `project_id`, `raw_summary`), не затирая неуказанные атрибуты; при отсутствии записи создает новую с валидными временными метками `CURRENT_TIMESTAMP`.
5. **Двойной интерфейс вызова:**
   - Поддерживает как объектно-ориентированный стиль через класс `DatabaseManager.<method>`, так и функциональный стиль через модуль-левел алиасы (`from antigravity_migrator.db_manager import extract_workspace_uri, ...`).

### Результаты тестирования
- `tests/test_db_manager.py`: 10 тестов, 100% pass (0.018s).
- Проверены:
  - `extract_workspace_uri`: чтение из подполя 1 поля 1 (`WorkspaceInfo`), прямой строки в поле 1, поля 7, обработка отсутствующих файлов, пустых баз, поврежденных блобов.
  - `update_trajectory_metadata`: создание новой записи, атомарное обновление существующей, проверка сохранения данных.
  - `load_conversation_summaries`: извлечение списков, проверка структуры полей, обработка несуществующих баз.
  - `update_summary_record`: полный апдейт, частичный апдейт (только `project_id`), вставка новой строки в несуществующую таблицу с автосозданием схемы.
  - `busy_timeout`: подтверждение установки значения 5000 мс в соединении.

### Принятые архитектурные решения
1. **Надежное извлечение заголовка из транскрипта (`extract_title_from_transcript`):**
   - Построчное чтение JSON Lines (`transcript.jsonl`) с потоковой обработкой: при обнаружении синтаксических ошибок в отдельных строках парсер продолжает обработку валидных строк.
   - Извлечение содержимого из блоков `<USER_REQUEST>...</USER_REQUEST>` либо прямого текста из первого пользовательского шага (`USER_INPUT` / `USER_EXPLICIT`).

   - Генерация валидного формата `title` и блока `last_user_view_time` (`seconds`, `nanos: 0`).

4. **Управление файлами аннотаций (`ensure_annotation_file`):**
   - Автоматическое создание родительских директорий при необходимости.
   - Защита от непреднамеренной перезаписи по умолчанию (`overwrite=False` возвращает `False`).

   - Предоставлен класс-обертка `AnnotationGenerator` со статическими методами и прямой экспорт функций модуля (`AnnotationGenerator`, `extract_title_from_transcript`, `generate_annotation_pbtxt`, `ensure_annotation_file`).

## 2026-09-29: Промпт 1.6 - Менеджер атомарных снапшотов и отката (backup_manager)

### Принятые архитектурные решения
1. **Атомарные снапшоты данных (`create_snapshot`):**
   - Создание изолированной директории снимка с временной меткой вида `YYYY-MM-DD_HH-MM-SS` (с суффиксом разрешения коллизий `_N` при создании нескольких снимков за одну секунду).
   - Целевое резервное копирование критических компонентов: одиночные файлы `agyhub_summaries_proto.pb`, `conversation_summaries.db`, а также каталоги `annotations/` и `conversations/`.
   - Исключение нецелевых временных папок и кэшей (`brain/`, `.backups/`, сторонних логов).
2. **Аппаратное ускорение APFS Copy-on-Write на macOS:**
   - На macOS (`platform.system() == "Darwin"`) используется клонирование блоков файловой системы без дублирования дискового пространства через `cp -c` (для файлов) и `cp -Rc <src>/. <dst>` (для каталогов).
   - Бесшовный fallback на стандартные `shutil.copy2` и `shutil.copytree(dirs_exist_ok=True)` при сбоях clonefile (2), неподдерживаемых файловых системах или запуске на Linux/Windows.
3. **Контроль целостности и манифест (`manifest.json`):**
   - При создании снапшота формируется криптографический манифест с точным размером и контрольной суммой SHA-256 для каждого скопированного файла, а также общим объемом и таймстемпом.
   - Метод `restore_snapshot` перед накатом данных выполняет валидацию всех файлов по манифесту. При обнаружении повреждения, несоответствия хеша или утери файла операция немедленно прерывается со статусом `False`, защищая рабочую директорию от повреждения.
4. **Управление точками восстановления (`list_snapshots`):**
   - Сканирование каталога бэкапов с чтением метаданных из манифестов и динамическим расчетом fallback-метрик для внешних или ручных каталогов.
   - Сортировка снимков в хронологическом порядке (наиболее свежие первыми).
5. **Высокоуровневый фасад (`BackupManager`):**
   - Поддержка интеграции с `PathManager` для автоматического разрешения корневых путей данных и снимков (`data_dir` / `.backups`).
   - Единый API: `create_snapshot()`, `list_snapshots()`, `restore_snapshot()`.

## 2026-09-29: Промпт 1.5 — Монитор процессов и безопасное ожидание завершения (process_watcher)

### Принятые архитектурные решения
1. **Кроссплатформенное обнаружение процессов Antigravity (Ponytail & Fallback):**
   - Первичный механизм: использование `psutil.process_iter(['pid', 'name'])` для высокопроизводительного сканирования процессов без запуска внешних утилит.
   - Отказоустойчивый fallback: при отсутствии библиотеки `psutil` или системных ограничениях автоматически переключается на нативные утилиты ОС:
     - macOS / Unix: `ps -A -o pid=,comm=` с извлечением базового имени исполняемого файла через `os.path.basename`.
     - Windows: `tasklist /FO CSV /NH` с парсингом CSV-вывода стандартным модулем `csv`.
2. **Точная фильтрация целевых процессов (`is_antigravity_process_name`):**
   - Выявление процессов Antigravity IDE (`Antigravity`, `Antigravity IDE`, `Antigravity.exe`, `Antigravity IDE.exe`) и вспомогательных процессов Electron (`Antigravity Helper` и его подпроцессы renderer/gpu/plugin).
   - Выявление языкового сервера (`language_server`, `language_server_macos`, `language_server_linux`, `language_server_windows_x64.exe`, `language_server.exe`).
   - Исключение сторонних инструментов и утилит (`antigravity-tools`, `antigravity-chat-migrator`, `AntigravityQuota`).
3. **Безопасное ожидание завершения («холодная» запись, `wait_for_shutdown`):**
   - Немедленный возврат `True`, если процессы изначально не были активны (нулевые задержки при запуске на выключенной IDE).
   - Циклический опрос `poll_interval` (по умолчанию 0.5с) до истечения `timeout_seconds`.
   - Обязательная защитная пауза `safety_pause` (по умолчанию 1.0с) после выхода последнего процесса для сброса дискового кэша ОС и финализации WAL-логов SQLite.
4. **Высокоуровневый фасад (`ProcessWatcher`):**
   - Объектно-ориентированный интерфейс с методами `is_running()`, `get_pids()`, `wait_for_shutdown()`.
   - Экспорт всех функций и классов в корневом пакете `antigravity_migrator`.

### Результаты тестирования
- `tests/test_process_watcher.py`: 11 тестов, 100% pass (0.04s).
